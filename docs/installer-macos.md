# Установщик под macOS — проработка

Статус: **обсуждение, код не написан.** Составлено 2026-09-20.

## Задача

Собрать настоящий установщик, а не скрипт с открытым кодом. Он должен:

* поставить серверную часть со своей иконкой;
* явно показать адрес, по которому доступен сервер;
* по галочке поставить Übersicht как обязательную часть виджета;
* принести с собой всё, что нужно для работы, — пользователь ничего не
  доустанавливает.

## Решения

| Вопрос | Решение |
|---|---|
| Übersicht | **скачивать** при установке, не класть внутрь |
| Значок в строке меню | **делаем** |
| Автозапуск при входе | **галочкой**, не принудительно |
| `cloudflared` | **не нужен**, выбрасываем |
| Формат | `.pkg` — только он умеет галочки |
| Переезд состояния в `~/Library/Application Support` | **обдумать**, решения нет |
| Apple Developer | **вопрос открыт**, см. «Подпись» |

## Что уже есть

`build_mac.sh` собирает `.app` через PyInstaller (`--onefile`, иконка
`build_assets/VinylPlayer.icns`) и упаковывает в DMG с ярлыком на
`/Applications`. Внутрь уже попадает всё, что нужно серверу: Python, `httpx`,
`mutagen`, `vkpymusic`, `musicbrainzngs`, `certifi`.

**Это правильная основа, её менять не надо:** зависимости приезжают в
комплекте, `pip` на машине пользователя не запускается никогда.

Два наблюдения из кода:

* **`Pillow` ставится при сборке, но в коде не используется** — ноль
  упоминаний `PIL`. Выбросить;
* **`cloudflared` весит 37 МБ из 41 МБ всего приложения.** Раз он не нужен,
  приложение худеет примерно до 4 МБ. Это заодно ускоряет нотаризацию.

Отдельный установщик виджета уже написан — `macos-widget/setup.command`. Его
логика пригодится, но станет частью общего установщика.

`LaunchAgent` в системе нет: сервер сейчас поднят чем-то другим, вручную или
из виджета.

## Почему `.pkg`

Галочка «поставить виджет» и есть развилка. DMG умеет только «перетащи в
Applications» — выбора там не бывает. Варианты установки описываются файлом
`Distribution` внутри `.pkg`.

Три пункта:

| Пункт | Что делает | По умолчанию |
|---|---|---|
| Сервер | `.app` в `/Applications` | обязательно, снять нельзя |
| Виджет на рабочий стол | ставит Übersicht + наш виджет | по выбору |
| Запускать при входе | `LaunchAgent` | по выбору |

## Übersicht — скачиваем

Решено не класть внутрь: это чужое приложение, и его распространение — вопрос
лицензии, который не хочется тащить в свой установщик.

Значит `postinstall`-скрипт при выбранной галочке:

1. проверяет, не стоит ли Übersicht уже (и тогда ничего не качает);
2. скачивает с сайта проекта, проверяет контрольную сумму;
3. кладёт в `/Applications`;
4. копирует `vinyl-player.widget` в
   `~/Library/Application Support/Übersicht/widgets/`;
5. запускает Übersicht.

**Что важно:**

* нужен интернет в момент установки — без него галочка должна честно сказать
  об этом, а не молча провалиться;
* скрипт, который качает и запускает чужой код, усложняет нотаризацию — это
  придётся учесть при подписи;
* виджет ставится в домашнюю папку, поэтому установщик работает в
  пользовательском домене, а не системном;
* при обновлении Übersicht мы не отвечаем за его версию — нужна проверка
  минимальной совместимой.

## Значок в строке меню

Это единственное место, где нужен новый код, а не упаковка. И он же решает
задачу «явно показать адрес».

Почему адрес нельзя зашить в установщик: **на момент установки он неизвестен.**
Зависит от сети, от mDNS-имени машины и от того, выпущен ли сертификат
Let's Encrypt. Зашитый в ярлык адрес протухнет при первой же смене сети.

Значок в строке меню показывает:

* состояние — сервер работает или нет;
* **текущий адрес** с кнопками «открыть» и «скопировать»;
* «остановить» / «запустить»;
* «настройки» — открывает веб-интерфейс.

Адрес берётся у самого сервера (`/api/config` на локальном порту), поэтому
всегда актуален.

Чем делать — открытый вопрос: маленькая обёртка на Swift или Python-библиотека
для статус-бара. Swift даёт нативный вид и чистую подпись, но это второй язык
в проекте, где сейчас всё в одном файле.

## Подпись и нотаризация — главное нерешённое

Без подписи macOS на **чужой** машине скажет «программа повреждена и не может
быть открыта». Обходится правым кликом или командой в терминале — то есть
получается ровно то, от чего мы уходим.

Полноценная подпись требует:

* **Apple Developer, 99 долларов в год**;
* два сертификата: Developer ID Application и Developer ID Installer;
* нотаризацию через `notarytool` и `stapler`.

Техническая цена: нотаризация требует hardened runtime, а он плохо дружит с
`--onefile` — распаковка во временную папку при каждом запуске упирается в
защиту. **Придётся перейти на `--onedir`**, где бинарники лежат отдельно и
подписываются по одному.

Хорошая новость: без `cloudflared` подписывать чужие бинарники больше не надо.

**Пока решения нет.** Без Apple Developer установщик имеет смысл делать только
«для своих», с инструкцией на первый запуск.

## Что ещё понадобится

**Удаление.** `.pkg` не умеет деинсталлировать. Нужен пункт «Удалить» в
приложении или отдельный скрипт: снять `LaunchAgent`, убрать виджет, удалить
`.app`. Про файлы состояния спросить отдельно — там сертификат Let's Encrypt,
токен DuckDNS, учётные записи, история прослушиваний и плейлисты. Молча это
сносить нельзя.

**Обновления.** Сейчас приложение умеет обновлять только PWA (через
`/api/version`), но не себя. Для `.app` это отдельный механизм — либо Sparkle,
либо проверка версии с предложением скачать новый `.pkg`.

**Интерфейс WAN.** Раз `cloudflared` выбрасывается, переключатель WAN должен
либо исчезнуть, либо честно говорить, что туннель не установлен. Сейчас код
уже умеет «cloudflared не установлен», но кнопка в интерфейсе остаётся.

## Переезд состояния — обдумать

Сейчас всё лежит в `~/.vinyl_*`: учётные записи, настройки, сертификаты, кэш
релизов, избранное, история прослушиваний. По соглашениям macOS место для
этого — `~/Library/Application Support/`.

Аргументы за переезд: так принято; пользователь не видит мусор в домашней
папке; удаление приложения становится понятнее.

Аргументы против: это **миграция живых данных**. Без неё теряются сертификат
Let's Encrypt, токен DuckDNS, учётные записи и вся история прослушиваний. Плюс
пути зашиты в двух десятках мест кода, а в `docs/wip.md` и `CLAUDE.md` они
описаны как есть.

Если переезжать — нужен перенос старых файлов при первом запуске новой версии,
с сохранением прав 600 и с откатом, если что-то пошло не так.

## Порядок работ, когда возьмёмся

1. Выбросить `Pillow` и `cloudflared`, перейти на `--onedir`, проверить, что
   приложение всё ещё собирается и работает.
2. Значок в строке меню с адресом — отдельно и до упаковки, потому что это
   единственная часть с новым кодом.
3. `LaunchAgent` и его установка-снятие.
4. `postinstall` для Übersicht и виджета.
5. `.pkg` с тремя пунктами и `Distribution`.
6. Подпись и нотаризация — если будет Apple Developer.
7. Удаление.
8. Отдельно и позже: переезд состояния, если решим переезжать.
