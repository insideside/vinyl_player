# Powered — улучшение качества треков (Apollo)

Статус: **план согласован, код не написан.** Составлено 2026-09-16.

## Задача

Установка по желанию, только в серверной версии (не в PWA). Выбранные треки
улучшаются моделью Apollo: она дорисовывает срезанные сжатием высокие частоты
и сглаживает артефакты MP3. Результат сначала живёт рядом с оригиналом, в
системном плейлисте Powered, и только по явному подтверждению заменяет трек в
библиотеке. Две копии обязательны до подтверждения; оригинал после замены
сохраняется и возвращается.

## Факты, на которых стоит план

**Скорость — примерно реальное время.** Замер из документации Apollo под
macOS: M3, 6 с аудио через MPS — 5.78 с, пик памяти 4.8 ГБ; на CPU — 316 с.
Трёхминутный трек ≈ 3 минуты, 226 кандидатов из `vlad1503` ≈ полсуток.
Интерфейс строится вокруг очереди и фоновой работы. CPU как запасной путь не
годится — в 50 раз медленнее.

**Модель обучена на MP3 24–128 kbps.** На 256+ заметной разницы ждать не стоит,
на 320 — тем более.

**Ключ истории содержит расширение** (`Артист - Трек.mp3`, `_denumber_name` /
`cacheKey`). Результат в том же формате — ключ не меняется. Смена формата —
перенос истории, якорей периодов, ссылок в плейлистах и ключа кэша.

**Плейлист играет только то, что есть в `tracks[]`** (`tracks.findIndex`,
остальное молча пропускается). Powered-версии обязаны быть в `tracks[]` с
признаком «не библиотека». Цена — около 25 мест, обходящих `tracks[]` (18
циклов, 7 вызовов методов массива): каждое проверить и там, где смысл
«библиотека», исключить. Плеер, кэш, виджет, окно метаданных — без изменений.

**Окружение.** Apollo проверен на Python 3.10 + PyTorch 2.11 + numpy 1.26.
Сервер работает на 3.13, для него нет колёс numpy 1.26 — на 3.13 будет
numpy 2.x, совместимость не проверена. Если не заработает — установщик ставит
отдельный Python 3.12 через `uv`. Лицензия кода и весов — CC BY-SA 4.0.

**Кодировщиков в системе нет** — ни `lame`, ни `ffmpeg`. MP3 кодируется внутри
окружения Powered (биндинги LAME), проверяется на спайке.

**«Только lossless» в радио считает по формату файла** (`cfg.lossless && !t.fmt`,
`fmt` из расширения и кодека) — улучшенный FLAC попадёт туда автоматически.

## Что улучшаем на самом деле

Перевод MP3 во FLAC сам по себе ничего не даёт — тот же звук в файле в
несколько раз больше. Сжатие MP3 выбрасывает звук: у 128 kbps обычно срезано
всё выше ~16 кГц, плюс артефакты — «звон» перед ударами, «булькающие»
тарелки. Apollo дорисовывает срезанные частоты и сглаживает артефакты. Это и
есть улучшение, а формат — только контейнер для результата.

Модель **не восстанавливает оригинал**: высокие частоты — правдоподобная
догадка, а не утерянные данные. Возможны артефакты («шипящие» тарелки,
металлический призвук на вокале). Отсюда обязательное A/B-прослушивание перед
заменой и резервная копия оригинала.

Повторное сжатие в MP3 на 320 kbps режет только выше ~20 кГц — почти всё
дорисованное сохраняется. На низких битрейтах повторное сжатие срезало бы его
снова, поэтому вариант «MP3 → MP3» — только 320.

## Что лежит в библиотеке

Снято сканом каталогов на 2026-09-16:

| Каталог | Треков | Состав |
|---|---|---|
| `insideside` | 725 | FLAC, lossless |
| `vlad1503` | 2489 | MP3: **2263** — 256–320 kbps, **121** — 160–255, **105** — ниже 160 |

Реальные кандидаты — ~226 треков из `vlad1503`. Оговорка: битрейт в теге не
доказывает качество — MP3 320, пересжатый из 128, обрезан так же, на ~16 кГц,
а с ВК такие попадаются. Честный детектор — анализ спектра (частота среза),
он отложен на потом.

## Выбор модели

|---|---|---|---|
| Весы | **67 МБ** | 363 МБ (8 бит — 681 МБ, PyTorch-оригинал — 3.32 ГБ) | 6.18 ГБ |
| Параметров | 16.5 млн | 638 млн | — |
| Скорость | ~реальное время на MPS (замер на M3) | 1.10 RTF на Apple Silicon | тяжёлая диффузия |
| Выход | 44.1 кГц, стерео | 48 кГц, **только моно** | 48 кГц |
| Обучение | **MP3 24–128 kbps** | срез высоких частот | срез высоких частот |
| Лицензия | CC BY-SA 4.0 | CC-BY-NC 4.0 | открытая |
| Зависимости | PyTorch | MLX | PyTorch |

Выбран **Apollo**: учили ровно на восстановлении музыки после MP3, крошечные
веса, стерео. FlashSR — запасной вариант, если Apollo не понравится на слух:
моно (стерео — по каналам, то есть трёхминутный трек ~6–7 минут),
некоммерческая лицензия. AudioSR не рассматриваем — 6 ГБ и не видела
артефактов MP3.

## Ресурсы и объём приложения

Приложение сейчас: `vinyl_player.py` — 0.9 МБ, `.app` и `.dmg` — по 41 МБ;
ни `torch`, ни других ML-зависимостей в нём нет.

**В приложение модель не зашиваем.** Колесо PyTorch под macOS arm64 — 128 МБ
в сжатом виде, после сборки PyInstaller — сотни МБ; `.app` вырос бы до
~0.5–1 ГБ (оценка) у всех, включая тех, кому функция не нужна. Отдельное
окружение по кнопке:

| Набор | Примерно |
|---|---|
| Apollo + PyTorch | ~1–1.5 ГБ (оценка) |
| Apollo, если стоит ACE-Step (`docs/ai-generation.md`) | +67 МБ — PyTorch в его окружении уже есть |

Результаты: MP3 320 — ~7 МБ на трёхминутный трек, FLAC — ~25–35 МБ. Плюс
резервные оригиналы до их удаления.

Память при обработке: пик ~4.8 ГБ целиком, кусочная обработка — примерно
вдвое меньше (замеры документации Apollo на M3).

## Решения

| Вопрос | Решение |
|---|---|
| Формат результата | спрашивается при улучшении, правила ниже |
| MP3 от 320 kbps | только FLAC, альтернативы нет |
| FLAC | 16 бит, 44.1 кГц |
| Оригинал после замены | резервная копия + «Вернуть оригинал»; отдельная кнопка «удалить оригиналы» |
| Плейлист после замены | трек уходит из Powered — плейлист значит «ждёт решения» |
| Lossless-исходник | улучшать нельзя |
| MP3 256–319 | можно, с предупреждением |
| Кэш на PWA | кэшируется всё, включая Powered |
| Пункт меню до установки | показывается на сервере, ведёт к установке |
| Python, если 3.13 не подойдёт | отдельный 3.12 через `uv` |
| Анализ спектра | отложен: сначала по одному треку, потом пакетно |
| Радио | новый чип не нужен — «только lossless» уже есть |

### Правила выбора формата

| Исходник | Что предлагается |
|---|---|
| FLAC / ALAC / WAV / AIFF | улучшение недоступно: «трек уже без потерь» |
| MP3 до 255 kbps | выбор: **MP3 320** (по умолчанию) или FLAC |
| MP3 256–319 kbps | тот же выбор + предупреждение: модель учили на битрейтах до 128 |
| MP3 от 320 kbps | только **FLAC** + то же предупреждение |

Почему MP3 320 по умолчанию: кодировщик на 320 режет только выше ~20 кГц,
почти всё дорисованное сохраняется; файл ~7 МБ против ~25–35 МБ у FLAC; и
расширение не меняется — переносить историю не нужно. Минус — второе
поколение сжатия, но оригинал всё равно в резервной копии.

## Архитектура

### Хранение

```
<каталог>/.powered/
    Артист - Трек.mp3|flac    ← улучшенная версия, ждёт решения
    originals/                ← оригиналы после замены
    index.json                ← источник, формат, статус, даты, битрейт исходника
    renames.json              ← «старый ключ → новый», только для смены формата
```

Скан каталога не рекурсивный — папка в библиотеку сама не попадёт.
Powered-версии добавляются в ответ скана отдельно, с флагом. `/api/stream/`
отдаёт файл из подпапки: `_safe_path` это уже разрешает.

### Метка в самом файле

Улучшенный файл получает тег (ID3 `TXXX:POWERED` / Vorbis comment `POWERED`),
скан читает его в короткий ключ записи каталога — по конвенции проекта
(`yr`, `gen`, … и пустые не кладутся). Метка в файле, а не только в
`index.json`, потому что переживает перенумерацию, перемещение и замену. По
ней бейдж формата отличает улучшенный трек (⚡ рядом с MP3/FLAC).

**Радио.** Отдельный чип не заводим: «только lossless» уже есть
(`cfg.lossless && !t.fmt`, `fmt` из расширения и кодека), и Powered FLAC
попадает туда по формату, как любой FLAC. Имей в виду: исходник у такого
трека был сжатым, то есть «lossless» у него только контейнер. Если однажды
захочется отбирать в этот чип лишь настоящий lossless — метка `POWERED` уже в
файле, исключение займёт одну строку в отборе радио.

### Окружение и воркер

* `~/.vinyl_powered/` — venv, код Apollo (закреплённый коммит, нужны только
  `look2hear/models` и утилиты), веса `pytorch_model.bin` (67 МБ), свой
  `runner.py`. Итого ~1–1.5 ГБ, из них модель — 67 МБ.
* Установка — фоновый поток с шагами и процентами, как выпуск сертификата.
* Воркер — отдельный процесс: сервер однопоточный, а обработка идёт минутами.
  Модель грузится один раз на очередь, прогресс по кускам пишется в stdout
  строками, воркер выгружается после простоя — освобождает 3–5 ГБ памяти.
* Задания строго по одному: пик памяти ~4.8 ГБ, параллель ничего не ускорит.
* Кусочная обработка (`chunk 6 s, overlap 1 s, batch 1`) — рекомендация
  документации Apollo для MPS: память вдвое ниже, батчи на MPS не ускоряют.

### Только серверная версия

Все изменяющие ручки проверяют, что запрос с самой машины, и что пользователь
админ. PWA — только показ и воспроизведение.

### API

| Ручка | Что |
|---|---|
| `GET /api/powered/status` | установлен ли, очередь, задания с прогрессом |
| `POST /api/powered/install` / `uninstall` | окружение; готовые файлы при удалении остаются |
| `POST /api/powered/enhance` | `{files, format}` — в очередь |
| `POST /api/powered/cancel` | снять задание |
| `POST /api/powered/replace` | заменить в библиотеке |
| `POST /api/powered/revert` | вернуть оригинал |
| `POST /api/powered/discard` | удалить улучшенную версию |
| `POST /api/powered/purge_originals` | удалить резервные оригиналы |

## Интерфейс

**Настройки → Powered.** Состояние: не установлен / устанавливается N% /
готов. Кнопка установки сразу называет размер. Удаление окружения.

**Контекстное меню** — в библиотеке и в плейлисте Powered:
* один трек → «Powered…» → окно;
* несколько → «Powered: улучшить выбранные (N)» — один вопрос о формате на всю
  пачку; правила формата применяются к каждому треку (320+ всё равно уйдёт во
  FLAC, lossless-исходники пропускаются с пояснением).

**Значки в списке:** ⚡ — готова улучшенная версия, процент — в обработке.

**Окно Powered — четыре состояния:**

1. **Нет версии.** Формат и битрейт исходника, ожидаемое время («≈ 3 мин»),
   выбор формата по правилам выше, предупреждения, кнопка «Улучшить».
2. **Обрабатывается.** Полоса прогресса с оставшимся временем, «Отменить».
   Окно можно закрыть — работа идёт, прогресс виден на значке.
3. **Готово.** «Оригинал: MP3 128 kbps, 4 МБ» ↔ «Powered: MP3 320, 7 МБ» и
   **A/B-прослушивание с мгновенным переключением на той же позиции** —
   отдельный `<audio>` внутри окна (только десктоп, ловушки iOS не касаются).
   Кнопки: «Заменить в библиотеке», «Удалить улучшенную версию», «Улучшить
   заново».
4. **Заменено.** «Оригинал сохранён», «Вернуть оригинал».

**Подтверждение замены** перечисляет последствия: размер было/станет, для FLAC —
смена формата и перенос истории, плейлистов и периодов; оригинал уходит в
резервную копию.

**Плейлист Powered** — системный, как умные: без перетаскивания и правки
состава. Версии, ждущие решения. Синхронизируется на PWA.

## Замена

Общее для обоих форматов:
1. переносятся теги и обложка оригинала, ставится метка `POWERED`;
2. номер `NN. ` сохраняется;
3. оригинал → `.powered/originals/`;
4. улучшенный файл → в каталог под именем трека;
5. сбрасывается кэш скана библиотеки (`_collect_user_tracks_cached`, 120 с).

**MP3 → MP3:** ключ не меняется — история, периоды, плейлисты на месте. Нужно
только сбросить кэш на клиентах: под тем же ключом в IndexedDB лежит старая
версия. Признак смены — отметка времени замены, клиент при синхронизации
перекачивает такие записи.

**MP3 → FLAC:** ключ меняется, переносится:
* история прослушиваний — у всех пользователей этого каталога;
* якоря периодов (`.vinyl_eras.json`);
* ссылки во всех плейлистах каталога;
* запись в `renames.json` — прослушивания со старым ключом, накопленные PWA
  без сети, досылаются позже, и `record_plays` сводит их к новому;
* старый ключ в IndexedDB удаляется, новый кэшируется заново.

**Откат** — те же шаги в обратную сторону.

Если заменяемый трек сейчас играет — замена ждёт или перезапускает его с той
же позиции.

0. **Спайк без интерфейса — решение идти или нет.** Окружение в песочнице,
   Apollo на 2–3 настоящих MP3 через MPS: скорость и память на M4 Pro, чтение
   MP3, Python 3.13 + numpy 2, кодирование MP3 320. **И слушаем.** Разницы на

1. Установщик, воркер, очередь, API.
2. `.powered/`, метка в файле, скан с флагом, проверка ~25 обходов `tracks[]`.
3. Системный плейлист, синхронизация на PWA.
4. Меню, значки, окно с выбором формата, прогрессом и A/B.
5. Замена и откат: сброс кэша для MP3, перенос для FLAC.
6. Проверки на стенде, раздел в CLAUDE.md.

## Риски

* **Кэш на iPhone.** Решено кэшировать всё. Около 1 ГБ в IndexedDB роняет PWA на
  iOS (см. CLAUDE.md) — FLAC-версии приближают этот предел быстрее. При
  переполнении кэширование уже честно останавливается (`reason === 'db'`).
* **Совместимость с Python 3.13** — выясняется на спайке, запасной путь — 3.12.
* **MPS.** Поддержка операторов зависит от версий PyTorch и macOS; документация
  Apollo отмечает не фатальные предупреждения STFT на 2.11.
* **Кусочная обработка** даёт результат, немного отличный от обработки целиком —
  цена за память. На слух проверяется на спайке.
