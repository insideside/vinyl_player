# insideside music — заметки по кодовой базе

Контекст для работы над кодом. Пользовательская документация — в `README.md`, здесь её не дублируем.

## Что это

Локальный музыкальный веб-плеер: Python-сервер на `http.server` + одностраничное приложение,
которое ставится на iPhone как PWA. Импорт треков из VK/Яндекс/Spotify/Apple Music/SoundCloud,
поиск метаданных, плейлисты, офлайн-кэш, раздача по LAN/WAN.

## Архитектура: один файл

`vinyl_player.py` — ~11 300 строк, **всё приложение целиком**: сервер, HTML, CSS и JS.
Фронтенд живёт в Python-строках верхнего уровня:

| Блок | Что это |
|---|---|
| `SW_JS = r"""..."""` | Service Worker |
| `HTML_PAGE = r"""..."""` | всё приложение: разметка, стили, ~5000 строк JS |
| `LOGIN_PAGE = r"""..."""` | страница входа |

Плейсхолдеры подставляются при отдаче: `PORT_PLACEHOLDER` и `APP_BUILD_HASH` в `HTML_PAGE`,
`BUILD_HASH` и `SW_PORT` в `SW_JS`. `APP_BUILD_HASH` — это `md5(HTML_PAGE)[:8]`, он же ключ
SW-кэша и основа автообновления через `/api/version`.

Прочее: `android/` (обёртка Chaquopy), `macos-widget/` (виджет Übersicht),
`vk_music_downloader.py` (отдельная утилита), `build_*.sh|bat` (сборка).

## Два сервера, два порта

| Порт | Адрес | Схема | Кто ходит |
|---|---|---|---|
| `LOCAL_PORT = 7666` | `127.0.0.1` | всегда **HTTP** | Mac-приложение, виджет, локальный браузер |
| `SERVER_PORT = 7656` | `0.0.0.0` | **HTTPS** когда LAN включён | телефоны, другие устройства сети |

Локальный сервер работает всегда; LAN-сервер поднимается только при `IS_PUBLIC`. Разделение
намеренное: локальную точку входа нельзя ломать переключением LAN. Локальный URL открывается
по имени `localhost`, а не `127.0.0.1` — иначе браузер, увидев HTTPS на `127.0.0.1:7656`,
пинит HSTS на весь хост и апгрейдит даже HTTP-порт.

Оба используют `BaseHTTPRequestHandler` и **однопоточны**. Один долгий стрим блокирует все
остальные запросы — это заметно при массовом кэшировании и при отладке.

## HTTPS и сертификат

Самоподписанный, `~/.vinyl_cert.pem` / `~/.vinyl_key.pem`. SAN содержит все локальные IP,
`localhost` и mDNS-имя машины. Перевыпуск — только когда сертификата нет, он истекает или
не покрывает текущие адреса.

**Ловушка:** системный `openssl` в macOS — это LibreSSL, в нём **нет флагов `-ext` и `-addext`**.
Поэтому генерация идёт через `cryptography`, а чтение SAN — через `-text` (или ту же
`cryptography`). Раньше проверка покрытия падала в `except` и сертификат перевыпускался при
каждом запуске, из-за чего на iPhone приходилось заново принимать доверие.

**Ловушка:** TLS-ошибки рукопожатия (`_ssl_error_count`) **не повод** перевыпускать сертификат.
Это почти всегда клиент, который его ещё не принял; перевыпуск делал только хуже — получалась
петля, а текущие загрузки рвались.

## Адреса подключения и PWA

PWA намертво привязана к origin, с которого установлена. Установили по `https://192.168.1.101:7656` —
в другой Wi-Fi сети IP другой, приложение стучится в мёртвый адрес, а кэш (IndexedDB + Cache
Storage) привязан к origin и переехать не может.

Поэтому сервер отдаёт `lan_host_url` — стабильный адрес по mDNS-имени (`<имя>.local:7656`).
Имя определяется в рантайме (`scutil --get LocalHostName` в macOS, иначе `socket.gethostname()`)
и **отдаётся только если сервер сам может его разрезолвить**: `.local` работает лишь при живом
mDNS-ответчике (в macOS есть всегда, в Linux нужен avahi, в Windows — Bonjour). В сертификат
имя кладётся всегда. Результат кэшируется на 5 минут — `get_lan_host_url()` дёргается на каждом
`/api/config`, а внутри subprocess и DNS-запрос.

Safari и iOS резолвят `.local` через системный mDNS, **Chrome — нет** (свой DNS-резолвер,
даёт `DNS_PROBE_FINISHED_NXDOMAIN`). В подсказках это оговорено.

Спасательные пути, когда origin умер: диалог «Подключение к серверу» (профиль → «Адрес сервера»
или тап по офлайн-баннеру) и поле ввода адреса на SW-странице «Сервер недоступен».

## Хранилище на клиенте

**localStorage** (всё привязано к origin):

| Ключ | Что |
|---|---|
| `_vc_config` | последний конфиг с сервера |
| `_vc_folder_<путь>` | закэшированный каталог треков (~1 МБ на 2500 треков в UTF-16) |
| `_vc_playlists_<путь>` | плейлисты каталога |
| `_vc_hosts` | адреса серверов, введённые вручную |
| `_vc_playctx` | текущий трек и позиция (переживает перезапуск PWA) |
| `_vc_cachequeue` | остаток очереди кэширования |
| `_vc_player_mode` | вид плеера |

Квота origin — ~5 МБ, каталоги её съедают. Все записи идут через `lsSet()`, который при
переполнении вытесняет самые крупные `_vc_folder_*` и повторяет попытку: каталог всегда можно
пересканировать, плейлисты и конфиг — нет.

**IndexedDB** `vinylCache`, стор `audio` — плоский, `ArrayBuffer` по строковым ключам:
* аудио — ключ `cacheKey(file)`
* обложка — ключ `'cover:' + cacheKey(file)`

`cacheKey()` срезает префикс `NN. `: файлы на диске нумерованные, добавление трека
перенумеровывает весь каталог, и полное имя как ключ нестабильно. Блобы при этом **не
переносятся** — копирование ~1 ГБ роняет PWA на iOS; вместо этого `refreshCachedList()` строит
индексы `_audioKeyIndex` / `_coverKeyIndex` по одному только списку ключей.

## Ловушки, на которые уже наступали

**Ответ 200 ≠ полезные данные.** При истёкшей сессии `/api/*` отдаёт `{"error": "unauthorized"}`
со статусом **200**. Проверка `if (!r.ok)` это не ловит: 25 байт JSON попадали в IndexedDB как
обложка или как трек — навсегда, потому что «закэшировано» и повторно никто не качал. Сейчас
`/api/cover/` и `/api/stream/` отдают честный **401**, клиент проверяет `Content-Type` и
сигнатуру файла при записи и при чтении, испорченные записи чинятся сами.

**Service Worker маскирует падение сервера.** На неудачный `/api/*` он возвращает **200 с
`{error:'offline'}`**. Поэтому `r.ok` и отсутствие reject ничего не значат: нужно смотреть на
тело. Из-за этого `userPlaylists = d.playlists || []` затирал кэш плейлистов пустотой, а
страница «Сервер недоступен» уходила в цикл перезагрузок по `r.ok`.
SW **не перехватывает** `/api/stream/`, `/api/cover/`, `/reset`, `/icon.png` и любой
кросс-доменный запрос (иначе проба чужого адреса всегда выглядит успешной).

**`OFFLINE_FALLBACK` внутри `SW_JS` — строка в одинарных кавычках.** Каждый обратный слэш
съедается JS-строкой раньше, чем браузер разберёт HTML: регулярка `/\/+$/` приезжает как
`//+$/` и комментирует остаток скрипта. **Этот блок пишем без обратных слэшей вообще.**
Проверка: `eval` строкового литерала, затем `node --check` вытащенного инлайн-скрипта.

**Смена `audio.src` порождает событие `pause`.** Отличить её от системного прерывания можно
только флагом — все присвоения идут через `setAudioSrc()`, флаг снимается по `loadstart`.
Эвристика по `readyState` не работает: приложение подменяет src на blob уже после старта.

**`scrollTo({behavior:'smooth'})` в Chrome на длинных списках с ленивыми картинками молча
не срабатывает** (побеждает scroll anchoring). В Safari работает. Поэтому — фолбэк на
мгновенную прокрутку, если через 250 мс позиция не сдвинулась.

**Обрыв связи не должен прокручивать очередь вхолостую.** `fetch` падает мгновенно, и цикл
кэширования за секунды «проходил» сотни треков, ничего не скачав. `cacheTrack` различает
причины: `http` (сервер ответил «нет» — трек пропускаем), `net` (связь/TLS — файл остаётся
в голове очереди, повторы с паузой, затем остановка), `db` (хранилище переполнено).

**Индикатор офлайна при живом Wi-Fi.** `navigator.onLine` остаётся `true`, когда недоступен
только сервер, — событие `offline` не придёт. Ловим по телу ответа `/api/config` и `/api/version`.

**Поиск.** Отображаются теги (`title`/`artist`), а имя файла на диске пишется иначе
(`Smack That (Slowed & Reverb).mp3` против тега `Smack That(Slowed & Reverb)`, `Артист, Артист`
против `Артист/Артист`). Поэтому в стог сена входят оба источника, пунктуация схлопывается
в пробелы, слова матчатся по «И».

## iOS: что можно и чего нельзя

Нельзя автоматически вернуть себе Now Playing после того, как аудио перехватило другое
приложение: iOS отдаёт слот перехватчику и назад не возвращает, события «прерывание закончилось»
в вебе нет, `play()` без жеста заблокирован. После холодного старта PWA не появится в Пункте
управления, пока не проиграет звук по жесту.

Что делается вместо этого: `mediaSession.playbackState` всегда актуален (`'none'` — повод для
iOS выкинуть страницу из Пункта управления), трек и позиция сохраняются вне страницы и
восстанавливаются **на паузе** — первое нажатие продолжает, а не начинает заново.

Автозапуска при восстановлении нет намеренно.

## Локальный запуск для проверок

Не трогать запущенный экземпляр пользователя. Изолированный инстанс на своих портах:

```python
import importlib.util, sys, pathlib, time, socketserver
spec = importlib.util.spec_from_file_location("vp", "/путь/vinyl_player.py")
vp = importlib.util.module_from_spec(spec); sys.modules["vp"] = vp; spec.loader.exec_module(vp)
vp.SERVER_PORT = 17656; vp.LOCAL_PORT = 17666
vp.CERT_FILE = pathlib.Path("test_cert.pem"); vp.KEY_FILE = pathlib.Path("test_key.pem")
vp.IS_PUBLIC = True
vp.Handler._get_user = lambda self: next(iter(vp.load_users()))   # обойти авторизацию
class T(socketserver.ThreadingMixIn, vp.ReusableHTTPServer): daemon_threads = True
vp.ReusableHTTPServer = T          # иначе стрим блокирует все запросы
vp._start_server("0.0.0.0")
while True: time.sleep(1)
```

Важно:
* сервер читает `HTML_PAGE` при импорте — **после правки JS перезапускать процесс**;
* браузер отдаёт страницу из SW-кэша — перед проверкой снимать регистрацию SW и чистить
  `caches`, иначе тестируется старый билд (наступал на это несколько раз);
* `/api/public` и `/api/cert/renew` пишут в общий `~/.vinyl_settings.json` — в тестах не дёргать;
* после тестов чистить `indexedDB.deleteDatabase('vinylCache')` — иначе на диске остаются
  гигабайты закэшированных треков;
* в headless-подобном Chrome медиа не проигрывается (`readyState` не выходит из 0), логику
  воспроизведения проверять подменой `duration` / `currentTime` на элементе.

Проверка синтаксиса перед запуском:

```bash
python3 -c "import ast,io; ast.parse(io.open('vinyl_player.py',encoding='utf-8').read())"
# и node --check для JS, вытащенного из HTML_PAGE / SW_JS
```

## Конвенции

* Язык в коде смешанный, и это устоявшаяся практика: построчные комментарии почти всегда
  английские (в JS 404 из 408, в Python 212 из 229), а **docstring-и функций — русские**
  (40 из 60). UI-строки и сообщения пользователю — по-русски. Комментарии объясняют
  **почему**, а не что.
* Стиль JS — строго ES5: во всём приложении ноль стрелочных функций и ноль `let`/`const`,
  только `var` и `function`. Сборки и зависимостей нет. Писать так же.
* Файлы состояния — в `$HOME`: `.vinyl_users.json`, `.vinyl_settings.json`, `.vinyl_cert.pem`,
  `.vinyl_key.pem` (все `chmod 600`). Плейлисты — `.vinyl_playlists.json` внутри каталога музыки.
* Правки в большой файл удобнее вносить точечными заменами по уникальной строке с проверкой
  `assert s.count(old) == 1`, а не переписыванием блоков.
