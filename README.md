# insideside music

insideside music — персональный музыкальный веб-плеер с визуализацией в стиле виниловой пластинки. Работает как локальное приложение или как сервер в домашней сети, доступный с любого устройства. Поддерживает импорт треков из VK, Spotify, Apple Music, Яндекс.Музыки и SoundCloud, автоматический поиск метаданных и обложек, создание плейлистов, офлайн-кэширование и установку как PWA на iPhone/iPad.

---

## Локально или сервер?

**Локальный режим** (по умолчанию) — плеер запускается на `http://127.0.0.1:7666` и доступен только на вашем компьютере. Подходит для персонального использования.

**Серверный режим (LAN/WAN)** — плеер становится доступен другим устройствам в локальной сети (LAN) или через интернет (WAN). Все подключённые устройства используют одну библиотеку, но каждый пользователь имеет собственный аккаунт и набор каталогов.

> **Порты.** Локальный доступ всегда работает по обычному HTTP на порту **7666** (`http://127.0.0.1:7666`) — этот адрес не меняется и не зависит от LAN/WAN, его и стоит использовать на самом компьютере (например, для иконки в Dock). LAN/WAN работает по HTTPS на порту **7656** (`https://<IP>:7656`) и поднимается только при включении сетевого режима. Оба сервера работают параллельно, поэтому переключение LAN не разрывает локальный доступ, а адрес для других устройств (порт 7656) не меняется.

## Установка

### Требования

- Python 3.7+
- macOS / Linux / Windows
- `openssl` (для HTTPS в режиме LAN — обычно предустановлен)
- `cloudflared` (опционально, только для WAN-режима через Cloudflare Tunnel)

### Установка зависимостей

```bash
python -m pip install mutagen httpx vkpymusic musicbrainzngs
```

На **Windows** дополнительно установите пакет для HTTPS (на macOS/Linux обычно не требуется — используется системный `openssl`):

```bash
python -m pip install cryptography
```

| Пакет | Назначение |
|-------|------------|
| `mutagen` | Чтение и запись метаданных аудиофайлов (ID3, FLAC, M4A) |
| `httpx` | HTTP-клиент для запросов к внешним API |
| `vkpymusic` | Интеграция с VK Music (поиск и скачивание треков) |
| `musicbrainzngs` | Поиск метаданных в базе MusicBrainz |
| `cryptography` | Генерация HTTPS-сертификата (Windows, опционально на Linux) |

### Поддерживаемые форматы

MP3, FLAC, M4A, OGG, WAV, AAC, OPUS.

### Запуск

```bash
python3 vinyl_player.py
```

Плеер автоматически откроется в браузере по адресу `http://127.0.0.1:7666`.

Для запуска сразу в LAN-режиме:

```bash
python3 vinyl_player.py --public
```

### Установка Cloudflare Tunnel (опционально, для WAN)

**macOS:**
```bash
brew install cloudflared
```

**Linux (Debian/Ubuntu):**
```bash
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install cloudflared
```

**Windows:**
```powershell
winget install Cloudflare.cloudflared
```

## Учётные записи

### Первый запуск — создание администратора

При первом запуске вы увидите форму создания аккаунта администратора. Укажите логин, пароль и корневую папку для музыки (по умолчанию `~/VinylMusic`). Администратор создаётся один раз — это главный аккаунт с полными правами.

### Управление пользователями

Администратор может добавлять новых пользователей через панель управления (кнопка с иконкой шестерёнки в верхней панели). Для каждого пользователя задаются логин, пароль и роль.

**Роли пользователей:**

| Возможность | Админ | Пользователь | Демо |
|-------------|:-----:|:------------:|:----:|
| Слушать музыку | ✓ | ✓ | ✓ |
| Добавлять каталоги | ✓ | ✓* | — |
| Скачивать из VK / импорт | ✓ | ✓ | — |
| Поиск метаданных | ✓ | ✓ | — |
| Перемещать / переименовывать треки | ✓ | ✓ | — |
| Управлять плейлистами | ✓ | ✓ | — |
| Включать LAN/WAN | ✓ | — | — |
| Управлять пользователями | ✓ | — | — |
| Скачивать ZIP-архив каталога | ✓ | — | — |

\* Пользователь может добавлять каталоги только внутри корневой папки музыки.

**Демо-аккаунт** — режим «только слушать». Демо-пользователь видит только специальную папку `_demo` и не может изменять библиотеку. Удобно для гостевого доступа.

### Безопасность

- Пароли хранятся в виде хэша PBKDF2-SHA256 (260 000 итераций, индивидуальная соль для каждого пользователя)
- Сессии — HttpOnly cookie с атрибутом SameSite=Strict и 30-дневным сроком действия
- Защита от перебора паролей: максимум 5 попыток на IP и на пользователя за 5 минут, плюс глобальный лимит 20 попыток
- Файлы конфигурации, сессий и сертификатов доступны только владельцу (chmod 600)
- Защита от path traversal на всех файловых эндпоинтах

## Каталоги

### Корневая папка музыки

При первом запуске задаётся корневая папка (по умолчанию `~/VinylMusic`). Администратор может изменить её в панели управления. Внутри неё для каждого пользователя автоматически создаётся подпапка с его логином.

### Работа с каталогами

- **Добавить каталог** — нажмите кнопку «+» в верхней части панели. Откроется файловый браузер для выбора папки на диске. После выбора каталог появится в выпадающем списке
- **Удалить каталог** — нажмите кнопку «−» рядом с выбранным каталогом. Удаляется только привязка к аккаунту, файлы на диске остаются нетронутыми
- **Переключение** — выберите нужный каталог из выпадающего списка. Плеер просканирует папку и покажет все найденные аудиофайлы

### Разграничение прав между пользователями и каталогами

- **Администратор** видит все каталоги всех пользователей и может добавлять любые папки на диске без ограничений
- **Пользователь** видит только свои каталоги и может добавлять папки только внутри корневой папки музыки (защита MUSIC_ROOT sandbox)
- **Демо** видит только папку `_demo`, без возможности добавления

Администратор может назначить конкретные каталоги каждому пользователю через панель управления → список пользователей → настройка папок.

## Серверный режим

### LAN — доступ в локальной сети

1. Включите тумблер **LAN** в верхней панели (виден только администратору на локальной машине)
2. Сервер автоматически сгенерирует самоподписанный HTTPS-сертификат и перезапустится на `0.0.0.0`
3. В информационной строке появятся LAN-адреса (например, `https://192.168.0.157:7656`), а также стабильный адрес по имени компьютера (например, `https://MacBook-M4-Pro.local:7656`)
4. Откройте этот адрес на другом устройстве в той же Wi-Fi сети
5. При первом подключении браузер покажет предупреждение о самоподписанном сертификате — нажмите «Дополнительно» → «Перейти на сайт»

**Какой адрес выбрать.** IP-адрес выдаёт роутер, и в другой сети он будет другим. Адрес вида `имя-компьютера.local` (mDNS/Bonjour) не меняется никогда — сертификат выписывается и на него тоже. Safari и iOS такие имена резолвят, Chrome — нет (у него собственный DNS-резолвер), поэтому в Chrome пользуйтесь IP.

Имя определяется на сервере при запуске (`scutil --get LocalHostName` в macOS, иначе `hostname`), так что на любой другой машине подставится её собственное. Показывается оно только если сервер сам может его разрезолвить: в macOS mDNS-ответчик есть всегда, в Linux нужен `avahi-daemon`, в Windows — Bonjour. Если ответчика нет, `.local`-адрес нигде не упоминается и остаются только IP.

При выключении тумблера LAN сервер возвращается в локальный режим. Состояние LAN сохраняется в настройках и автоматически восстанавливается при перезапуске сервера.

HTTPS включается автоматически — он необходим для работы Service Worker (кэширование приложения и офлайн-режим) на устройствах, подключённых по сети.

### WAN — доступ через интернет

Два способа (тумблер **WAN** в верхней панели):

- **Cloudflare Tunnel** — выберите режим «Tunnel». Сервер получит публичный HTTPS-адрес вида `https://xxx-xxx.trycloudflare.com`. Требуется установленный `cloudflared`. Адрес меняется при каждом включении
- **Статический IP** — укажите ваш внешний IP и порт вручную. Требуется настройка проброса портов (port forwarding) на роутере. Настройка сохраняется и восстанавливается при перезапуске

### Использование на других устройствах

1. Откройте LAN- или WAN-адрес в браузере устройства
2. Войдите под своим аккаунтом (или попросите администратора создать аккаунт для вас)
3. Интерфейс приложения автоматически закэшируется через Service Worker — при следующих визитах страница загрузится мгновенно, даже если сервер временно недоступен

**Кэширование треков для офлайн-прослушивания:**

- Кнопка ↓ рядом с треком — скачать один трек в кэш браузера
- Кнопка ↓ в шапке списка треков — скачать все треки текущего каталога
- Кнопка ↓ на плейлисте — скачать все треки плейлиста (уже скачанные пропускаются)
- Фильтр «Только кэш» ✓ — показывает только кэшированные треки, счётчик обновляется
- В офлайн-режиме фильтр кэша включается автоматически с уведомлением

Треки хранятся в IndexedDB браузера. Размер кэша отображается в профиле пользователя (иконка пользователя).

## Импорт треков из внешних источников

### VK Music

Для скачивания из VK необходима авторизация:

1. Нажмите «Авторизация VK» в нижней части панели
2. Перейдите по ссылке авторизации — откроется страница VK OAuth
3. После авторизации VK перенаправит на страницу с токеном в URL
4. Скопируйте весь URL из адресной строки и вставьте в поле ввода

**Важно о безопасности VK-токена:**
- Токен хранится **только в оперативной памяти** сервера
- Токен **не сохраняется на диск** и **никуда не передаётся** — при перезапуске сервера авторизацию нужно пройти заново
- Токен используется исключительно для доступа к аудиозаписям через API VK и ни для чего другого

После авторизации вы можете:
- Вставить ссылку на плейлист VK для массового скачивания
- Искать и скачивать отдельные треки через встроенный поиск VK

### Импорт из других источников

Поддерживается импорт плейлистов из Spotify, Apple Music, Яндекс.Музыки и SoundCloud.

| Источник | Как работает |
|----------|-------------|
| **Spotify** | Парсинг списка треков из публичного плейлиста по ссылке |
| **Apple Music** | Парсинг треков через iTunes API |
| **Яндекс.Музыка** | Парсинг через API Яндекс.Музыки |
| **SoundCloud** | Парсинг плейлиста через API SoundCloud |

Импорт работает в два этапа: сначала из внешнего сервиса извлекается список треков (название + исполнитель), затем каждый трек ищется и скачивается через VK Music. Поэтому для импорта из любого источника необходима авторизация VK.

## Организация коллекции

### Нумерация треков

Треки хранятся в формате `0001. Исполнитель - Название.mp3`. Числовой префикс определяет порядок воспроизведения. Ширина нумерации (количество цифр) автоматически подстраивается под общее количество треков.

При скачивании из VK можно выбрать, куда вставить новые треки:
- **Сверху** — новые треки получат номера от 0001, существующие сдвинутся вниз
- **Снизу** — новые треки добавятся после последнего существующего
- **В определённую позицию** — треки вставятся в указанное место, остальные автоматически перенумеруются

### Перемещение треков

- **Drag-and-drop** — включите режим редактирования (кнопка с карандашом в шапке списка), перетащите треки в нужном порядке, нажмите сохранить (✓). Все файлы будут переименованы с новой нумерацией
- **Через редактирование трека** — откройте редактирование (долгое нажатие или правый клик → меню), укажите новый номер в поле «Порядок». Трек переместится на указанную позицию, остальные сдвинутся

При любом перемещении нумерация всех треков в каталоге автоматически пересчитывается для сохранения последовательности без пропусков.

### Переименование и удаление

- **Переименование** — откройте редактирование трека, измените название и/или исполнителя. Файл будет переименован на диске, теги в аудиофайле (ID3, Vorbis и т.д.) обновлены
- **Удаление** — через контекстное меню трека (правый клик или долгое нажатие) → «Удалить». Файл удаляется с диска безвозвратно, требуется подтверждение

### Плейлисты

- **Создать** — вкладка «Плейлисты» → «+ Создать плейлист»
- **Добавить треки** — контекстное меню трека → «Добавить в плейлист» → выбрать нужный плейлист
- **Воспроизвести** — раскройте плейлист нажатием и нажмите «Воспроизвести». Очередь воспроизведения будет построена из треков плейлиста
- **Редактировать** — кнопка с карандашом на плейлисте: изменение названия, удаление треков
- **Удалить** — через редактирование → «Удалить плейлист»
- **Изменить порядок** — перетаскивание плейлистов drag-and-drop

Плейлисты хранятся в файле `.vinyl_playlists.json` внутри каталога и привязаны к папке, а не к пользователю.

## Что происходит с данными офлайн

**Сервер — единственный источник правды.** Плейлисты лежат в `.vinyl_playlists.json` внутри каталога музыки, треки — это файлы на диске. Создание плейлиста, удаление и перемещение треков, правка тегов — всё это записи на сервер; в браузере хранятся только копии для чтения. Поэтому «Обновить приложение» ничего не обнуляет: кнопка снимает регистрацию Service Worker и чистит кэш приложения, не трогая ни localStorage, ни скачанные треки в IndexedDB.

**Обратная сторона:** офлайн изменения не сохраняются вовсе — очереди отложенных записей нет. Попытка создать плейлист без связи с сервером завершается сообщением «Нет связи с сервером — изменение не сохранено», при этом окно редактирования **остаётся открытым вместе с набранным списком**: когда связь появится, достаточно нажать «Сохранить» ещё раз, ничего не набирая заново.

## Новинки артистов (вкладка DROPS)

Раздел показывает, что вышло у артистов, которые уже есть в вашей библиотеке.

**Кого отслеживать, приложение решает само.** Список нигде не задаётся: он пересчитывается из текущего каталога по двум признакам — сколько у артиста треков и насколько недавно вы его пополняли. Свежесть берётся из позиции трека в каталоге (файлы пронумерованы от новых к старым); для ненумерованных каталогов — из времени изменения файлов. Счёт растёт логарифмически от числа треков и умножается на свежесть, поэтому артист с парой треков, добавленных вчера, обгоняет артиста с сотней треков, которых не касались полгода. Пополнили или почистили библиотеку — список перестроился сам, исчезнувшие артисты выпадают из кэша.

Глубина проверки масштабируется от размера библиотеки, а не фиксирована. Плюс на каждом цикле добирается немного артистов из хвоста — тех, кого дольше всех не проверяли, — так что со временем покрываются все.

**Источник** — iTunes Search API, запасной — Deezer. Ни ключей, ни регистрации не нужно. Данные о релизах кэшируются в `~/.vinyl_releases.json`.

**Сколько показывается.** Дроп — это карточка релиза (альбом, EP или сингл), а не отдельный трек. Список отбирается по релевантности: вес складывается из близости артиста (сколько у него треков и насколько недавно вы его пополняли) и свежести релиза — анонсы и вышедшее на днях идут с полным весом, дальше он плавно падает. Показывается первая порция, в конце списка кнопка «Показать ещё» подгружает следующую из отсеянных. Один и тот же релиз, приписанный разным артистам, схлопывается в одну карточку.

**Проверка запускается только кнопкой** «Проверить» вверху списка. Сама по себе она не срабатывает: обход артистов ходит во внешние API и занимает пару минут, и делать это в фоне, когда никто не просил, плеер не должен. Открытие вкладки лишь показывает уже собранное.

**Что показывается:** карточка с обложкой, артистом, названием, типом релиза (альбом / EP / сингл) и датой, сгруппированные по свежести — «Скоро» для анонсированных, дальше за месяц, три месяца, полгода. Релизы, которых **нет в вашей библиотеке**, подсвечиваются и получают кнопку загрузки: она открывает окно импорта, подставляет «артист — название» и сразу запускает поиск. Уже имеющиеся приглушены и помечены галочкой.

**Прослушать перед скачиванием.** Нажатие на карточку разворачивает список треков релиза — **и только его**: ничего не запускается, играющая музыка не перебивается, состав альбома можно просто посмотреть. Воспроизведение начинается лишь по явному действию: кнопка ▶ на карточке включает первый отрывок, нажатие на строку трека — именно его. Дальше отрывки идут подряд, под играющей строкой ползёт полоса прогресса, повторное нажатие ⏸ ставит на паузу, не сворачивая список. Основной плеер и отрывок никогда не звучат одновременно: запуск отрывка ставит плеер на паузу, запуск трека в плеере глушит отрывок. Плеер сам не возобновляется — превью проигрывается отдельным элементом, чтобы не потерять текущий трек и позицию.

Отрывки идут через сервер, а не напрямую: Apple отдаёт их с нестандартным типом `audio/x-m4p`, на который браузеры не обязаны реагировать (`canPlayType` возвращает пустую строку), а iOS Safari к типам аудио особенно придирчив. Сервер подменяет тип на корректный. Проксируются только адреса с закрытого списка хостов Apple и Deezer.

**Если у iTunes отрывков нет** — релиз не найден, превью не выложены, сервис недоступен или троттлит — тот же релиз ищется в Deezer по артисту и названию, и отрывки берутся оттуда (там это mp3). Работает и в обратную сторону. Запросы к обоим API идут с повторами и паузой: iTunes при частых обращениях рвёт соединение, и одна осечка не должна выглядеть как «данных нет».

**Избранное.** Звёздочка в углу карточки поднимает релиз в группу «Избранное» наверху списка. Отметки хранятся на сервере **отдельно для каждой учётной записи** (`~/.vinyl_starred.json`), поэтому переживают перезагрузку, чистку кэша браузера и видны на всех устройствах, где вы вошли под тем же пользователем. Вместе с отметкой сохраняется снимок самого релиза — закреплённое не пропадёт, даже если оно выйдет из окна дат или артист выпадет из проверки. Удобно для анонсов: отметили ожидаемый альбом — он висит сверху до выхода.

Обложки не ждут прокрутки: список наливается сверху вниз в фоне. Подгрузка идёт по одной картинке за раз и **полностью останавливается, пока играет музыка** — сервер однопоточный, и очередь запросов за обложками не должна мешать воспроизведению.

**Обложки хранятся локально.** В кэше новинок лежат только ссылки, поэтому раньше картинки тянулись с серверов Apple при каждом открытии вкладки. Теперь они идут через сервер, который складывает их в `~/.vinyl_release_art/` и отдаёт с диска — это переживает и перезапуск сервера, и чистку кэша браузера. Каталог ограничен 600 файлами (примерно 30 МБ), лишнее вытесняется по давности обращения. Скачиваются только те обложки, которые реально показывались.

**Без сервера раздел продолжает работать.** Лента и избранное зеркалятся в IndexedDB, поэтому вдали от дома вкладка не прячется, а показывает последнюю синхронизированную копию с пометкой, когда она сохранена. Кнопка «Проверить новинки» в этом режиме ходит **напрямую в iTunes** из браузера: артисты ранжируются по каталогам, уже лежащим в кэше. Отметки избранного, поставленные без сервера, копятся и уезжают на него при первом же успешном ответе.

Автономный режим сознательно урезанный: Deezer из браузера недоступен (у его API нет заголовка `access-control-allow-origin`), поэтому запасной источник и дисковый кэш обложек остаются серверными. Вкладка скрывается, только если и сервера нет, и сохранённой копии тоже.

Играющий отрывок останавливается при уходе с вкладки.

## Поиск метаданных

Плеер может автоматически найти и заполнить метаданные (исполнитель, альбом, обложка) для ваших треков.

### Как это работает

1. Откройте каталог с треками
2. Нажмите кнопку поиска метаданных (отображается в интерфейсе при наличии треков без полных метаданных)
3. Плеер проанализирует каждый трек, извлечёт из имени файла исполнителя и название, и отправит запросы к нескольким сервисам одновременно
4. Результаты отображаются как **предложения** — вы просматриваете найденные данные и выбираете, какие изменения применить

### Используемые сервисы

| Сервис | Что ищет | API-ключ |
|--------|----------|----------|
| **Deezer** | Исполнитель, альбом, обложка, дата релиза | Не нужен |
| **iTunes** | Обложка, альбом | Не нужен |
| **Genius** | Обложка (арт трека) | Не нужен |
| **MusicBrainz** | Исполнитель, альбом, обложка через Cover Art Archive | Не нужен |

Все сервисы используются без API-ключей — они предоставляют публичные API.

### Подтверждение изменений

Метаданные **никогда не применяются автоматически**. После завершения поиска вы получаете список предложений, где для каждого трека показаны найденные данные (новый исполнитель, альбом, обложка). Вы отмечаете нужные и нажимаете «Применить». Изменения записываются непосредственно в теги аудиофайла (ID3 для MP3, Vorbis Comment для FLAC/OGG, iTunes atoms для M4A).

Также можно запустить поиск для одного трека — через его редактирование.

## PWA на iPhone/iPad

insideside music можно установить как полноценное веб-приложение на iOS:

1. Откройте адрес плеера в **Safari** (только Safari поддерживает PWA на iOS)
2. Нажмите кнопку **«Поделиться»** (квадрат со стрелкой вверх)
3. Выберите **«На экран Домой»**
4. Приложение появится на рабочем столе как отдельная иконка

> **Ставьте PWA по адресу `имя-компьютера.local`, а не по IP.** Браузер привязывает Service Worker и весь офлайн-кэш к адресу (origin), с которого приложение установлено. Установите по `https://192.168.0.157:7656` — и в другой Wi-Fi сети, где ноутбук получит другой IP, установленное приложение будет стучаться в несуществующий адрес, а перенести кэш на новый IP невозможно. Адрес `.local` при смене сети остаётся прежним, поэтому кэш переживает переезд.

### Обложки-заглушки вместо кэшированных обложек

Кэш обложек и треков проверяется на запись и на чтение: сохраняется только то, что действительно является картинкой (по сигнатуре файла) или достаточно большим аудио. Записи, испорченные более ранними версиями (когда истёкшая сессия отдавала `{"error": "unauthorized"}` со статусом 200, и это тело попадало в кэш вместо обложки), обнаруживаются при чтении, удаляются и перекачиваются автоматически — вручную чистить кэш не нужно.

### Прерванная загрузка кэша

Если во время массового кэширования соединение с сервером пропадает (типичная причина — браузер перестал принимать HTTPS-сертификат), плеер не пролистывает очередь вхолостую: он делает несколько попыток с паузой, затем останавливается, сохраняет остаток очереди и предлагает перезагрузить приложение. После перезагрузки (и подтверждения сертификата, если браузер о нём спросит) загрузка продолжается с того же места автоматически. Треки, которые сервер отдать не может, пропускаются — их число показано в финальном уведомлении.

### Если приложение потеряло сервер

Когда сервер недоступен, появляется красный баннер «Офлайн-режим» — нажмите на него, откроется окно **«Подключение к серверу»** (оно же доступно в профиле → «Адрес сервера»). Там перечислены все известные адреса с индикатором доступности и есть поле для ручного ввода IP или имени хоста. Если приложение вообще не открывается, тот же ввод адреса есть на странице «Сервер недоступен», которую показывает Service Worker.

Переход на новый адрес не переносит кэш треков — это ограничение браузера. Постоянное решение — переустановить PWA по адресу `.local`.

### Что даёт PWA-режим

- **Полноэкранный режим** — без адресной строки Safari, приложение выглядит как нативное
- **Кэш приложения** — интерфейс загружается мгновенно через Service Worker, даже без сети
- **Кэш музыки** — закэшированные треки доступны полностью офлайн, хранятся в IndexedDB
- **Управление с экрана блокировки** — play/pause, переключение треков, обложка текущего трека через Media Session API
- **Автоматическое обновление** — при изменении приложения на сервере Service Worker обновляет кэш в фоне

### Особенности iOS

- Service Worker работает только по HTTPS или на localhost — при включении LAN-режима HTTPS активируется автоматически
- Сертификат перевыпускается только когда меняется набор адресов машины; принятое на iPhone исключение для самоподписанного сертификата при обычных перезапусках сервера сохраняется
- При первом запуске PWA может потребоваться восстановление аудиосессии iOS — плеер определяет эту ситуацию и восстанавливает воспроизведение автоматически
- **Контекст воспроизведения переживает перерыв.** Текущий трек и позиция сохраняются вне страницы, поэтому если аудио перехватило другое приложение (или iOS выгрузил PWA из памяти), при возврате плеер стоит на том же треке и в том же месте — первое нажатие продолжает, а не начинает заново. Состояние плеера всегда транслируется в Now Playing (`mediaSession.playbackState`), так что экран блокировки и Пункт управления не показывают «играет», когда музыка уже остановлена
- Полностью автоматически вернуть себе Now Playing после чужого аудио веб-приложение не может: iOS отдаёт слот перехватившему приложению и не возвращает его обратно, а после холодного старта PWA появляется в Пункте управления только после первого воспроизведения по жесту пользователя

## Возможности плеера

### Интерфейс

- **Виниловая пластинка** — анимация вращения с отображением обложки альбома, перетаскивание пластинки для перемотки
- **Адаптивный фон** — цвет фона подстраивается под обложку текущего трека
- **Два режима на мобильных** — переключение между пластинкой и списком треков через тумблер внизу экрана. На вкладке пластинки мобильные кнопки play/next скрываются, так как плеер имеет собственные контролы
- **Три вкладки** — Треки, Альбомы (группировка по альбомам с обложками), Плейлисты
- **Играть следующим** — в контекстном меню трека. Выбранный трек помечается в списке ярлыком «следующий» и подготавливается заранее, чтобы переключение с виджета или экрана блокировки на iOS срабатывало сразу. Повторный выбор убирает его из очереди
- **Поиск** — мгновенный поиск с фильтрацией в реальном времени: одно поле ищет и по метаданным (название, исполнитель, альбом), и по имени файла на диске, поэтому подходит любое из двух написаний трека. Знаки препинания игнорируются (`Smack That (Slowed` находит тег `Smack That(Slowed & Reverb)`), а несколько слов можно комбинировать из разных источников — `крид malo` найдёт трек, у которого исполнитель из тега, а название из имени файла
- **Контекстное меню** — правый клик или долгое нажатие на треке: воспроизвести, играть далее, добавить в плейлист, редактировать, удалить, кэшировать

### Воспроизведение

- Play/Pause, предыдущий/следующий трек
- Перемотка по прогресс-бару или вращением пластинки
- Режим перемешивания (shuffle) — перемешивает очередь, сохраняя текущий трек
- «Играть далее» — вставка трека следующим в очередь воспроизведения
- Очередь воспроизведения учитывает текущие фильтры и результаты поиска

### Сброс кэша

Если что-то пошло не так (устаревший кэш, проблемы с Service Worker), перейдите по адресу `/reset` — например, `http://127.0.0.1:7666/reset` (локально) или `https://<IP>:7656/reset` (на устройстве, подключённом по LAN). Это очистит все кэши браузера, удалит Service Worker и перенаправит на главную страницу.

## Развёртывание как сервер

### macOS

```bash
python3 -m pip install httpx mutagen vkpymusic musicbrainzngs
python3 vinyl_player.py --public
```

Для автозапуска при входе в систему создайте файл `~/Library/LaunchAgents/com.insideside.music.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.insideside.music</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/bin/python3</string>
        <string>/path/to/vinyl_player.py</string>
        <string>--public</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
</dict>
</plist>
```

```bash
launchctl load ~/Library/LaunchAgents/com.insideside.music.plist
```

При необходимости разрешите входящие подключения в Системные настройки → Брандмауэр.

### Windows

```bash
pip install httpx mutagen vkpymusic musicbrainzngs
python vinyl_player.py --public
```

Для автозапуска при входе в систему:

1. Нажмите `Win+R`, введите `shell:startup`
2. Создайте в открывшейся папке файл `insideside-music.bat`:

```bat
@echo off
cd /d "C:\path\to\vinyl_player"
python vinyl_player.py --public
```

Для доступа из сети откройте порт в брандмауэре:

```powershell
netsh advfirewall firewall add rule name="insideside music" dir=in action=allow protocol=TCP localport=7656
```

### Linux

```bash
python3 -m pip install httpx mutagen vkpymusic musicbrainzngs
python3 vinyl_player.py --public
```

Пример systemd-сервиса (`/etc/systemd/system/insideside-music.service`):

```ini
[Unit]
Description=insideside music
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/insideside-music
ExecStart=/usr/bin/python3 vinyl_player.py --public
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable insideside-music
sudo systemctl start insideside-music
sudo ufw allow 7656/tcp
```
